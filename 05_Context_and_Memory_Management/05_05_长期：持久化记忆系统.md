# 05.05 长期：持久化记忆系统

长期记忆系统提供跨会话、任务和智能体实例持久化的**可索引、可检索存储**。与中期技术依赖摘要的前向注入不同，长期系统支持**任意召回**：给定查询，系统检索最相关的已存储记忆，无论其创建于何时。

## 5.5.1 基础架构

### OS 启发的分层记忆

**MemGPT**（Packer et al., 2023）引入了关键抽象：将 LLM 的上下文窗口视为 RAM，外部存储视为磁盘，赋予模型显式调页信息进出的函数调用。与虚拟内存的类比是精确的：正如 OS 通过透明分页为应用提供更大内存的假象，MemGPT 通过透明的记忆管理为 LLM 提供更长上下文的假象。这篇论文首次显式建立了智能体记忆与 OS 记忆之间的联系。

### 观察-反思-检索三元组

**Generative Agents**（Park et al., 2023）在社交模拟智能体的语境中引入了 Memory Stream 架构：

- **Memory Stream**：以自然语言记录形式存储所有观察，附带时间戳和重要性评分
- **检索**：结合时效性（recency）、重要性（importance，写入时评分）和与当前查询的相关性三信号
- **反思**（reflection）：周期性将已存储观察合成为更高层次的洞察

消融实验表明：**观察、反思和检索三个组件各自独立贡献于行为质量**——移除任何一个都会产生可测量的退化。这一三元组至今仍是智能体记忆设计的标准模板。

### 动态遗忘与人格建模

**MemoryBank**（Zhong et al., 2024）在检索架构上增加了两项扩展：
- **动态遗忘机制**（受 Ebbinghaus 遗忘曲线启发）：记忆随时间指数衰减，频繁访问增强记忆，矛盾记忆被解决
- **分层用户人格摘要**：每日更新以反映累积交互

## 5.5.2 生产记忆系统

### Mem0：混合存储与工业采纳

Mem0（Chhikara et al., 2025）是目前部署最广的生产智能体长期记忆层：
- Python 包下载量：**1400 万+**
- GitHub stars：**41K**
- 原生集成：CrewAI、Flowise、Langflow

**架构**：组合三种存储后端——向量数据库（语义相似搜索）+ 图数据库（关系建模）+ KV 存储（快速事实检索）。

> 在 LOCOMO 基准上，Mem0 比 OpenAI 原生记忆准确率高 **26%**，同时使用的 token 仅为全上下文方法的 **10%**。

**Amazon Web Services 于 2025 年选择 Mem0 作为其 Agent SDK 的独家记忆提供商**——标志其从研究原型向生产基础设施的转变。

### A-MEM：动态知识网络

A-MEM（Xu et al., 2025）借鉴 Zettelkasten 知识管理系统，为每个新记忆生成结构化笔记（关键词、标签、上下文描述、动态语义链接），并在添加新记忆时**回溯更新已有相关笔记的上下文和属性**。这解决了检索系统的一个根本局限：已存储记忆的相关性在写入时可能不明显，其重要性只能在后续信息的关联中体现。

### Hindsight：从记忆中学习

Hindsight（Vectorize.io, 2025）的立场：大多数记忆系统关注"记住"，而真正的需求是"学习"。API 操作：`retain`（存储）、`recall`（检索）、`reflect`（生成整合记忆与当前上下文的响应）。在 LongMemEval 基准上达到 SOTA。

### Honcho：推理驱动的个性化

Honcho（Plastic Labs, 2025）构建的是**用户模型**而非用户事实存储。后台异步推理管线（"梦想"）持续处理历史交互，提取显式事实和关于偏好、沟通风格和目标的推理结论。其实体中心数据模型支持多智能体环境。

### cq：集体记忆

Mozilla AI 的 cq（Mozilla AI, 2025）填补了其他系统留下的空白：**跨智能体实例的共享记忆**。大多数长期系统是每智能体或每用户的；当多个智能体处理相关任务时，每个实例独立重新发现其他实例已知的内容。cq 是 MCP 原生的开放标准，在三级运作：本地知识 → 组织共享知识 → 跨团队知识。其**错误后钩子模式**（智能体遇到错误时自动查询集体知识库）为防止组织内重复解决相同错误提供了具体机制。

## 5.5.3 学术综述与分类法

- **Zhang et al.（2025）**：标准学术分类法，区分短期工作记忆与长期记忆（语义/程序/情境），形式化"写入-读取-管理"循环
- **Du（2026）**：POMDP 式智能体循环，三维分类法（记忆范围、存储格式、组合结构），三种工程模式：
  - 模式 A：单体上下文
  - 模式 B：上下文窗口 + 检索存储
  - 模式 C：带学习控制策略的分层记忆
- **Gao et al.（2023）**：RAG 综述为上述生产系统的检索层提供了理论基础
