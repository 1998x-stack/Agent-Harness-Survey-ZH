# 05.04 中期：会话状态与跨运行持久化

中期上下文管理填补了**活跃上下文窗口与完整长期记忆系统之间的空白**。核心问题：智能体如何在会话内的多个轮次之间——或同一任务的多次运行之间——保存和恢复状态。

工程价值极高：**几百个 token 的结构化工作状态**可以桥接上下文重置，否则智能体将丢失所有累积进展。

## 结构化笔记

最简单的技术：智能体维护一个持久笔记文件（通常为 `NOTES.md` 或 `todo.md`），在每次运行开始时读取，在上下文清除前更新。

Anthropic 通过 Claude 玩宝可梦数千步的案例说明了这一点。在没有关于记忆结构的任何显式指令的情况下，智能体自行：
- 绘制已探索区域的地图
- 维护战斗策略及其对特定对手结果的统计
- 跨上下文重置追踪目标

每次压缩步骤清除对话历史后，智能体读取自己的笔记，继续数小时的训练序列而不失去连贯性。

> **核心洞察**：笔记将工作记忆外部化。智能体不依赖对话历史来承载任务状态，而是将重要内容写入外部存储并按需读回。

## 基于文件的规划与任务外部化

结构化笔记的扩展形式将完整规划表示外部化到磁盘：

| 工具 | 功能 |
|------|------|
| **planning-with-files**（OthmanAdi, 2025） | 编码智能体工作流中的持久化文件规划 |
| **Trellis**（mindfold-ai, 2025） | 项目记忆与规范注入——选择性注入结构化项目状态 |

任务状态、规范、中间结果和依赖图在每个里程碑写入文件系统，下一次运行时有选择地加载。

## 跨运行注入

一种互补模式：捕获前次运行的关键输出，在下次运行开始时注入。

| 工具 | 机制 |
|------|------|
| **claude-mem**（thedotmack, 2025） | 插件式记忆层——捕获会话历史，提取对未来运行最有用的信息，追加到下一会话上下文 |
| **everything-claude-code**（affaan-m, 2025） | 15 万+ GitHub star 的社区仓库，最大规模的开源中期记忆模式集合 |

这些方法**无需向量数据库或图存储**，同时提供可观的跨运行连续性。

## 中期权衡

| 优势 | 局限 |
|------|------|
| 比纯窗口管理提供显著更强的连续性 | 信息从前次运行单向流向下次运行，不来自索引存储 |
| 基础设施成本是完整长期系统的零头 | 无法扩展到大量历史记录 |
| | 无法按需检索特定历史观察（只能注入摘要） |

当跨运行历史变大，或智能体需检索特定先前观察而非注入摘要时，中期技术必须与长期系统（§5.5）互补使用。
