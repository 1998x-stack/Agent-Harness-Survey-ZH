# 05.06 长周期技术：百轮以上保持连贯

前述各节分别处理单一时间跨度。长周期任务——大规模代码库迁移、多会话研究项目、扩展自主工作流——要求**同时协调三个层级**，并在每个节点对应用何种技术做出实时决策。

## 上下文压缩（Context Compaction）

压缩将接近极限的上下文窗口摘要化，并以累积状态的压缩表示重新启动执行。

Anthropic 详细描述了校准挑战：
- **摘要必须保留**：架构决策、未解决的 bug、实现细节
- **摘要必须丢弃**：冗余的工具输出、已融入后续步骤的中间推理

**推荐调优工作流**：先最大化召回（recall），捕获追踪中每个潜在相关信息，然后迭代改进精度（precision），移除多余内容。反过来做会导致智能体丢失后续需要的上下文——这种丢失不可恢复。

**工具结果清除**是最轻量的压缩形式：完整工具输出被替换为紧凑的路径引用。这可以持续应用，现已成为 Anthropic 开发者平台的产品级特性。

## 子智能体上下文隔离

当任务需要深入探索子主题时，探索本身产生大量中间上下文——这些上下文在子任务内部有用，但会**污染编排器对整体任务的视图**。

子智能体架构的解决方案：
- 将子任务分配给专用智能体，每个拥有**全新的上下文窗口**
- 子智能体仅返回 **1000-2000 token 的浓缩摘要**给编排器
- 详细探索上下文隔离在子智能体内部

**Manus 团队的细化**：
- **简单子任务**：完全不共享上下文
- **复杂子任务**：编排器的完整上下文传递给子智能体

共享上下文的代价很高：产生更大的预填充，消除不同系统提示间的 KV 缓存复用。隔离成本 vs 协调收益的权衡必须针对每类任务显式决策。

## 混合决策框架

生产部署不统一应用单一技术，而是根据任务结构在不同执行节点选择不同技术。

Anthropic（2026c）总结了四层框架：

| 何时 | 做什么 |
|------|--------|
| 始终需要的内容 | 预加载 |
| 条件性需要的内容 | 即时检索 |
| 窗口接近饱和时 | 压缩历史 |
| 子任务需要会污染编排器上下文的探索时 | 生成子智能体 |

**正确的责任划分**：上下文管理应是基础设施的职责，而非智能体的职责。当执行环境自动处理压缩和合并时，模型可以专注于任务推理。
