# 05.03 短期：管理活跃上下文窗口

短期上下文管理控制模型在单次推理步骤或会话内短序列步骤中看到的内容。这些决策对模型行为影响最直接，做错时代价最高。

## 系统提示校准

系统提示建立智能体的行为边界，每次调用消耗固定预算。Anthropic 将设计挑战描述为找到正确的**海拔高度**：

- 过于具体的提示引入脆弱的、维护负担重的逻辑
- 过于模糊的提示让模型缺乏具体指导

**实践模式**：有效的系统提示被组织为背景、指令、工具指导和输出格式等清晰划分的部分，使用 XML 标签或 Markdown 头部分隔。

**推荐工作流**：
1. 在最佳可用模型上从最小提示开始
2. 通过实证识别失败模式
3. 针对特定缺口添加定向指令

> 预先枚举每个边界情况倾向于膨胀提示而不提高可靠性。

## Token 高效的工具设计

工具定义是上下文的**主要消耗者**。每个 schema、名称、描述、参数类型在每次调用时都被注入。大型工具集可在智能体读取用户请求之前消耗数万 token。

**生产部署中浮现的原则**：

- **偏好更少、更具表达力的工具，而非大量窄工具菜单**
- 如果人类工程师在特定场景中无法说出哪个工具适用，则不应期望模型做得更好
- 工具应自包含、对错误鲁棒、预期用途明确，参数名应发挥模型优势

## 即时检索与渐进式披露

有效智能体不预加载所有潜在相关信息，而是维护轻量级标识符（文件路径、存储的查询、Web 链接），在任务展开时按需加载数据。

> Anthropic 将这一方法称为**渐进式披露**（progressive disclosure）。它镜像了人类专家的运作方式：我们不记忆语料库，我们构建外部索引系统并按需检索。

**Claude Code 的混合策略**：
- CLAUDE.md 文件在会话开始时加载以提供项目上下文
- glob 和 grep 命令让智能体按需导航和加载特定文件内容
- 同时避开索引过期问题和大预填充成本

环境元数据也携带隐含信号：文件大小暗示复杂度，命名约定提示目的，时间戳代理相关性。

## KV 缓存感知的上下文设计

提示缓存是生产智能体部署中**性价比最高的优化**，其收益完全取决于上下文的结构方式。

Manus 团队在五轮架构迭代后，将 KV 缓存命中率确定为"**生产阶段 AI 智能体最重要的单一指标**"，并指出：

> Claude Sonnet 上缓存 token 成本为 $0.30/MTok，而未缓存 token 为 $3.00/MTok（Manus Team, 2025）

**三条缓存设计规则**：

| 规则 | 内容 |
|------|------|
| **保持提示前缀稳定** | 系统提示开头的单个 token 差异会使后续所有内容的缓存失效 |
| **将上下文视为仅追加** | 修改过去的动作或观察会通过创建不同前缀序列破坏缓存复用 |
| **使用确定性序列化** | JSON 序列化中不稳定的键排序会无声地使相同请求的缓存失效 |

Manus 通过**上下文感知状态机**解决工具定义变更导致的缓存失效问题：在解码期间遮蔽不可用动作的 token logits，而非在运行时修改工具定义列表。
