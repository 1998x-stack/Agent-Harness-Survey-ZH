# 07.01 追踪与监控平台

智能体可观测性的基础是**结构化追踪收集**：将每次 LLM 调用、工具调用、检索步骤和上下文组装操作记录为可检查、过滤和重放的 span 树。

## 主流平台

| 平台 | 核心能力 |
|------|---------|
| **Langfuse** | 交互式追踪树、延迟火焰图、token 用量分解、成本归因仪表盘、提示版本管理 |
| **Opik**（Comet ML） | 同上 + 实验跟踪 |
| **Arize Phoenix** | 追踪 + 评估 |
| **MLflow** | 传统 ML 实验跟踪扩展至 LLM |

这些平台通常通过轻量级 SDK 包装器（如 `@traceable` 装饰器）以最小代码变更插桩智能体的函数调用。

## OpenTelemetry：事实上的标准

OpenTelemetry（OTel）已成为插桩标准。OTel 社区发布了**生成式 AI 语义约定**，定义了模型名称、温度、token 计数和延迟等 span 属性（OpenTelemetry, 2026）。

两个开源项目将这些约定操作化：

| 项目 | 功能 |
|------|------|
| **OpenLLMetry**（Traceloop） | LLM 提供商（OpenAI、Anthropic、Cohere）和向量数据库（Pinecone、Chroma、Weaviate）的自动插桩库，发出标准 OTel span |
| **OpenInference**（Arize AI） | OTel 对齐的语义约定 + 自动插桩，作为 Phoenix 的配套 |

通过构建在 OTel 之上，这些库允许智能体追踪数据流入团队已用于传统微服务监控的同一后端（Prometheus、Jaeger、Grafana、Datadog），降低采用智能体专用工具的操作开销。

## 更深层的插桩

### AgentSight：eBPF 系统级监控

AgentSight（Zheng et al., 2025）从**应用进程外部**监控智能体，使用 **eBPF** 在 SSL 边界拦截 TLS 加密的 LLM 流量以捕获意图，并监控内核事件（进程创建、文件 I/O、网络调用）以捕获动作。实时关联引擎将 LLM 响应链接到其触发的系统行为。

> 关键优势：系统级监控**无法被受损或配置错误的智能体绕过**，对安全关键部署尤为重要。CPU 开销低于 3%。

### AgentTrace：三表面日志框架

AgentTrace（AlSayyad et al., 2026）在三层"表面"上捕获结构化日志：

| 表面 | 内容 |
|------|------|
| **认知（Cognitive）** | 推理步骤、计划、反思、自我纠正 |
| **操作（Operational）** | 工具调用和 API 交互 |
| **上下文（Contextual）** | 环境状态和用户输入 |

认知表面对执行环境工程尤为关键，因为它捕获了显式的推理工件——这些记录为调试由**错误推理而非系统错误**引起的失败提供了原始材料。
