# 07.05 讨论：走向统一可观测性

## 可观测性-评估鸿沟

LangChain 调研揭示了一个结构性断层：**89% 的团队使用追踪工具，但仅 52% 使用评估框架**（LangChain, 2025a）。这两类工具由不同社区以不同接口开发。

弥合这一鸿沟需要更紧密的集成：

- 从**生产故障追踪中自动生成回归测试用例**
- 将**在线评估分数作为告警信号**

LangChain 对深度智能体评估的分析和 Anthropic 对基础设施噪声的量化都主张：**评估和可观测性必须作为单一反馈循环来处理，而非分离的关注点。**

## 统一可观测性的关键要素

| 要素 | 含义 |
|------|------|
| **追踪与评估的统一** | 同一条追踪数据既支撑调试也支撑评估，避免重复插桩 |
| **跨层可见性** | 从 API 级 token 追踪到基础设施级 GPU 利用率，从模型推理到环境状态 |
| **因果归因** | 不仅知道"发生了什么"，还能追溯到"为什么发生" |
| **自动化闭环** | 检测 → 根因分析 → 推荐修复 → （可选）自动化修复 |

当前生态系统的状态是：**各组件功能强大但彼此隔离**。下一阶段的可观测性工程需要将这些组件集成为一个连贯的反馈系统，使执行环境能够在运行时自我诊断和自我修复。
