# 07.03 成本追踪与优化

LLM 推理按 token 计费，智能体执行环境放大成本暴露——单个面向用户的任务可能触发数十次 LLM 调用，每次调用都有各自的提示组装、工具结果注入和响应生成。

可观测性需求是双重的：**追踪**（知道 token 花在哪里）和**优化**（为相同结果消耗更少 token）。

## 追踪侧

| 工具 | 方式 |
|------|------|
| **TensorZero** | 统一 LLMOps 栈，将网关、可观测性、实验和优化打包为单一服务，支持每次调用和每个任务的成本归因 |
| **Helicone** | 极简方案——作为即插即用代理，无需代码变更即可增加成本和延迟监控 |

## 优化侧

### FrugalGPT：基础公式

FrugalGPT（Chen et al., 2023）提出三种降本策略：提示适配、LLM 近似和 LLM 级联。

> 自适应级联通过将简单查询路由到更便宜的模型，可在匹配 GPT-4 性能的同时实现最高 **98% 的成本降低**。

### GPTCache：语义缓存

GPTCache（Bang, 2023）提供语义缓存层，在查询到达 LLM 之前使用嵌入相似度检索缓存响应来拦截重复或改写查询。

### QC-Opt：质量感知路由

QC-Opt（Shekhar et al., 2024）在预算约束下联合优化模型选择、token 数量和延迟，使用 BertScore 预测器估计输出质量。

### TALE：Token 弹性悖论

TALE（Han et al., 2025）发现了一个重要细微差别：**将思维链推理的 token 预算设得太低可能反而增加 token 消耗**——因为模型会溢出其预算，生成比适度预算提示更多的 token。

### Dual-Pool Token-Budget Routing

在基础设施层面，将同质 vLLM 集群划分为短上下文和长上下文池，按估算 token 预算路由请求。在 Azure LLM Inference 和 LMSYS-Chat-1M 上评估，**减少 31-42% 的 GPU 小时**（预计 A100 集群规模下年省 $286 万）。

## 对执行环境工程师的启示

成本可观测性必须**跨越多层**：

| 层 | 关注点 | 工具 |
|-----|--------|------|
| API 级 | Token 追踪 | Helicone、TensorZero |
| 应用级 | 路由决策 | FrugalGPT、QC-Opt |
| 基础设施级 | 资源利用 | Dual-Pool、KV 缓存占用 |

**关键警告**：Anthropic 关于基础设施噪声的研究（Anthropic, 2026a）表明，仅基础设施配置即可使基准分数偏移 **6 个百分点**（p < 0.01）。这意味着**成本优化和评估保真度紧密交织**——为节省成本而削减资源可能在缺乏细粒度可观测性的情况下无声地降低智能体性能。
