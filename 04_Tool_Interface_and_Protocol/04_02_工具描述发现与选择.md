# 04.02 工具描述、发现与选择

一旦协议定义了**如何**发起调用，下一个瓶颈是**哪些**工具应该在每一步被呈现和选择。越来越多的研究关注工具文档质量、检索和动态候选剪枝。

## 关键研究

| 工作 | 聚焦问题 |
|------|---------|
| **EASYTOOL**（Yuan et al., 2025） | 从大型工具清单中选择合适工具的挑战 |
| **AnyTool / CRAFT**（Du et al., 2024; Yuan et al., 2023） | 通过自动构建或精炼工具使用流水线来减少人工指定负担 |
| **MetaTool**（Huang et al., 2023） | 基准式评估——工具检索和调用质量在不同领域和查询形式下存在显著差异 |
| **MCP-Zero / ToolRet / ToolRegistry**（Fei et al., 2025; Shi et al., 2025b; Ding, 2025） | 检索感知的编排和注册表质量是下游智能体成功的一阶决定因素 |

## 从工具扩展到技能

一个密切相关的研究方向将工具选择扩展到**可复用技能（skills）**——智能体不仅需要识别紧凑的 API schema，还需要识别相关的程序化模块。

- **SkillRouter**（Zheng et al., 2026）
- **SkillRet**（Cho et al., 2026）

两者都在大规模上研究技能选择问题，强调从庞大且重叠的技能库中检索正确技能的需求。

## 系统级设计原则

这些研究结果强化了两条设计原则：

### 原则一："少而精的工具"优于暴力暴露

原因：
- 缩小提示熵（prompt entropy）
- 减少规划器分支因子（planner branching）
- 降低 token 开销

### 原则二：发现管线必须是自适应的

静态的全局工具列表无法扩展到：
- 快速演进的工具仓库
- 多租户企业部署

工具发现和选择机制必须能够根据上下文动态调整候选集。
