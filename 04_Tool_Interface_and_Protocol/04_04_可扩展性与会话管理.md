# 04.04 可扩展性与会话管理

长周期运行中的一个反复出现的运维挑战是**工具会话管理**。

## 有状态会话的双刃剑

有状态工具会话改善了连续性，但增加了记账复杂性，尤其在调用被并行化或跨多个智能体委托时更为突出。

### 典型失败模式

| 失败模式 | 描述 |
|---------|------|
| **过期句柄**（Stale handles） | 长时间运行后工具会话引用失效 |
| **不一致的工具状态**（Inconsistent tool state） | 重试时工具状态未正确同步 |
| **上下文窗口饱和**（Context-window saturation） | 冗长的工具追踪记录填满上下文窗口 |

## 有效的执行环境设计要求

为应对上述失败模式，执行环境设计需要：

### 1. 显式的工具会话生命周期控制

定义清晰的会话创建、使用、销毁和恢复语义，而非将生命周期管理隐式地推给模型或提示。

### 2. 有界的工具上下文注入

不将所有工具输出全量注入上下文窗口，而是实施选择性、摘要化或渐进式的上下文注入策略。

### 3. 可观测性钩子以归因错误

清晰的错误归因路径至关重要：错误应能被追溯到**规划器逻辑**（选错了工具或参数）还是**接口/协议故障**（工具调用本身失败）。

## 生态系统视角

生态系统级的全景策展可以帮助实践者快速映射可用的协议和工具选项。但**基于基准的比较**对于决定特定部署中应采用哪种协议和工具路由策略仍然不可或缺。
