# 02.05 项目收集流程

我们采用系统性综述的报告规范来构建语料库，确保来源渠道、搜索策略和筛选过程的透明性和可复现性（Page et al., 2021）。如图 5 所示，候选项目从四个渠道收集：

## 四大来源渠道

| 渠道 | 内容 |
|------|------|
| **前人综述与基准论文** | 已有文献中涉及的执行环境相关项目 |
| **GitHub 可复现搜索** | 基于项目名称、描述、README 文本、主题标签、星标数、最近更新和存档状态的结构化搜索 |
| **精选项目列表与包注册表** | 社区维护的项目列表和包管理平台上的相关条目 |
| **企业工程博客与发布说明** | 引入执行环境级机制的官方技术文档（OpenAI, 2026a; Anthropic, 2025d; LangChain, 2026b 等） |

## 搜索策略

代表性查询组合了以下术语：

> `agent harness`、`coding agent`、`LLM agent sandbox`、`MCP server`、`agent observability`、`agent memory`、`agent evaluation`、`agent governance`

## 元数据记录

对于每个保留的候选项目，我们记录了：

- 项目名称
- URL
- 工件类型
- 来源类型
- 可用性状态
- 可识别的发布年份
- GitHub 元数据（如有）
- 用于后续 ETCLOVG 编码的公开证据

**元数据快照冻结日期**：2026 年 5 月 8 日。
