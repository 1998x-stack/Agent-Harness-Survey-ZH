# 02.01 智能体系统的演进

从早期链式思维提示到自主智能体的发展轨迹，可以被理解为**工程表面（engineering surface）的持续扩展**——即实践者必须管理的基础设施范围在不断增长。

## ReAct 时代（2022–2023）

Yao et al. (2023) 确立了"观察-思考-行动"（observe-think-act）循环作为智能体的基础原语。早期系统以极简的基础设施运行：一个 while 循环、一个提示模板、一个小型工具调度表。

**AutoGPT 和 BabyAGI** 通过引入任务队列、记忆和工具调度，展示了完全自主运行的雄心，同时也将关键失败模式暴露为基础设施问题而非单纯的提示问题（Significant Gravitas, 2023; Nakajima, 2023）：

- 执行失控（execution runaway）
- 上下文膨胀（context blowout）
- 状态丢失（state loss）
- 未被监控的副作用（unmonitored side effects）

这些失败模式表明：**智能体可靠性不是提示质量的问题，而是系统基础设施的问题**。

## 工具集成与多智能体协调（2023–2024）

这一时期，研究焦点从"模型能否使用工具"转向"如何让工具使用变得工程化可控"：

**工具使用能力的学习与诱导：**
- **Gorilla**、**ToolLLM** 和 **Toolformer** 证明工具使用能力可以被学习或诱导，而非只能硬编码到固定的 API 包装器中（Patil et al., 2024b; Qin et al., 2024; Schick et al., 2023）

**多智能体协调模式涌现：**
- **CAMEL**：基于角色扮演对话的协调
- **ChatDev**、**MetaGPT**：模拟软件开发组织结构的协调
- **Mixture-of-Agents**：分层智能体聚合（Li et al., 2023a; Qian et al., 2023a; Hong et al., 2023; Wang et al., 2024）

**评估基础设施成熟：**
- **SWE-bench**、**AgentBench**、**WebArena**、**GAIA** 等基准测试使智能体评估首次具备了可复现性（Jimenez et al., 2024; Liu et al., 2023a; Zhou et al., 2024; Mialon et al., 2023）

**协议标准化起步：**
- Anthropic 的 **MCP**（Model Context Protocol）和 Google 的 **A2A**（Agent-to-Agent）协议开启了智能体接口标准化进程（Anthropic, 2024c; Surapaneni et al., 2025）

## 执行环境转折点（2025–2026）

到 2025 年，积累的部署经验已经足以得出一个清晰的结论：**智能体可靠性的关键约束是基础设施质量，而非模型质量。**

2026 年初的三项独立发展验证了这一转折：

| 发展 | 内容 | 意义 |
|------|------|------|
| **OpenAI** | 正式将"执行环境工程"确立为独立学科 | 行业领导者的范式确认 |
| **Meta-Harness**（Stanford/MIT） | 自动执行环境优化超越手工工程 | 方法论的量化验证 |
| **DeepAgents**（LangChain） | 纯执行环境改进将 Terminal-Bench 2.0 得分从 52.8% 提升至 66.5% | 基础设施增益 ≈ 26% 相对改进 |

从 ReAct 的简单 while 循环到今日七层执行环境，工程表面的扩展同时带来了复杂性和可靠性。理解这一演进是理解后续各层设计的基础。
