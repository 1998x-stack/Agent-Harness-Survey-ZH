# 09.05 审计基础设施

治理需要问责。审计基础设施记录**智能体做了什么、为什么做、治理策略是否被遵守**——支持事后调查、合规监管和持续策略精化。

## 结构化审计轨迹

| 系统 | 审计记录内容 |
|------|-------------|
| **AutoHarness**（AIMing Lab, 2026） | 每次工具调用的 JSONL 记录——工具名、参数、风险分类、权限决策、执行结果、token 成本、延迟 |
| **SAGA**（Syros et al., 2025） | 扩展到多智能体交互——密码学 token 交换记录，支持跨信任边界来源追踪 |

**可重放审计记录的最低要求**：追踪标识符、责任者身份、工具调用、策略决策及版本、执行结果、资源成本、相关输入输出的完整性哈希。

> 大多数当前系统只记录其中一部分字段，且很少签名或哈希记录——**审计轨迹易受受损智能体进程的日志篡改**。

## 异常检测：逐动作 vs 轨迹级

| 粒度 | 方式 | 优势 | 局限 |
|------|------|------|------|
| **逐动作** | 对每个工具调用按风险分类 | 廉价、易审计 | 无法识别跨多次良性动作分布的慢速攻击 |
| **轨迹级** | 联合评估动作序列 | 捕获多步攻击 | 更高延迟、告警定位不精确 |

- **AgentMonitor**（Naihin et al., 2023）：轻量级日志+标记实现
- **AgentAuditor**（Luo et al., 2025）：行为模式匹配 + LLM 推理
- **SentinelAgent**（He et al., 2025）：多智能体通信建模为时序图，标记异常交互模式

实践中，逐动作检查**在线部署**，轨迹级分析**异步运行于审计日志**。

## 成本与资源审计

失控智能体循环可在循环密集型工作负载中快速耗尽 API 预算。**2025 OWASP LLM Top 10**（OWASP Foundation, 2025）将资源耗尽列为独立风险类别。

AutoHarness 追踪每次调用 token 消耗并通过宪法声明式执行会话级预算——在多智能体架构中尤为关键，扇形展开模式可指数级放大 API 调用。

## 分层治理管线

新兴设计模式将前述机制集成到单一可配置管线中。**AutoHarness** 以三层范例：

| 层级 | 深度 |
|------|------|
| **核心** | 解析→风险→权限→执行→审计 |
| **标准** | + 上下文丰富化 + 输出验证 |
| **增强** | + 异常评分 + 人工升级 + 形式约束验证 |

层级通过 YAML 宪法声明式选择——**治理开销随部署风险扩展**。

## 开放挑战

- 审计日志在长周期智能体中快速积累——存储、隐私和信噪比挑战
- 日志可能包含敏感用户数据、API 密钥或对话内容——审计完整性与数据保护存在张力
- 缺乏标准化审计 schema，跨系统分析和监管报告困难
