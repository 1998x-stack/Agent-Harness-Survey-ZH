# 09.03 组件加固

生命周期钩子在执行环境层面执行治理。组件加固强化各个智能体组件——特别是 LLM 及其调用的工具——针对其特定漏洞。执行环境从加固组件中受益，因为更少的恶意输入能存活到触发治理钩子。

## 模型加固

### 指令层级（Instruction Hierarchy）

Wallace et al.（2024）提出训练模型**优先处理特权指令**（系统提示）而非低特权指令（用户消息、工具输出）。模型学习在低层指令与高层约束一致时对齐，冲突时忽略或拒绝。

### SecAlign：偏好优化防御

SecAlign（Chen et al., 2025a）将同一防御目标形式化为对提示注入输入、期望响应和不期望响应的偏好优化。

> 模型加固补充而非替代执行环境级钩子。加固模型在推理时拒绝更多注入，但**无法阻止不受约束的数据流或未经授权的动作**——这些需要系统级执行。

## 分类器驱动的运行时加固

**Llama Guard**（Inan et al., 2023）微调独立模型，按可配置安全分类法对用户提示和助手响应分类，返回每类标签——执行环境可据此决定放行、阻止或升级。

**两个实用属性**：
- 分类法可在不重新训练智能体模型的情况下编辑
- 同一检测器可跨异构 LLM 后端复用

代价是延迟预算——每个额外分类器每次工具使用周期增加一次前向传递。

## 工具加固与 MCP 安全

### 攻击面

- **Radosevich & Halloran（2025）**：主流商业 LLM 可被胁迫使用 MCP 工具执行恶意代码、建立远程访问和窃取凭证。其 **McpSafetyScanner** 使用三智能体架构（黑客、审计员、监督者）系统发现漏洞
- **Trail of Bits（2025）**：MCP 服务器可通过**有毒工具描述**在用户调用任何工具之前就攻击客户端

### 防御

**ETDI**（Bhatt et al., 2025）：以密码学签名和版本化的工具定义扩展 MCP——任何对工具代码、模式或权限的修改都需要新的签名版本，防止无声升级的"rug-pull"攻击。

## 协议级加固

**SAFEFLOW**（Li et al., 2025）将细粒度信息流控制与事务执行语义结合——违规的工具调用或智能体间消息可以**回滚**而非通过共享状态传播。

## 供应链风险

**Slopsquatting**（Spracklen et al., 2025）：分析 16 个 LLM 的 576,000 代码样本发现，开源模型以 **21.7% 的比率幻觉出不存在的包名**。攻击者可注册这些幻觉名称在公共仓库注入恶意代码。ETDI 的密码学签名部分解决 MCP 工具的此问题，但包管理器和检索源仍超出大多数智能体治理栈。

## 开放挑战

- 无统一框架连接模型加固和工具加固
- 加固模型仍可能调用受损工具，签名工具定义不能防止被越狱模型滥用
- 将这些防御组合为具有**可量化残余风险**的连贯栈仍是开放问题
