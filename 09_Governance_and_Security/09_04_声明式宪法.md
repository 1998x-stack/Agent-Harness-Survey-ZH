# 09.04 声明式宪法

将治理逻辑直接嵌入应用代码使策略不透明、难以审计和难以更新。越来越多的执行环境将治理规则外部化为声明式配置文件（通常为 YAML），作为智能体的机器可读宪法。

## 训练时宪法：Anthropic 的 Constitutional AI

Anthropic（Anthropic, 2026a）发布了按四层优先级组织的宪法：

```
安全（人类监督） > 伦理（诚实、避免伤害） > 合规（Anthropic 指南） > 有用性（用户请求）
```

区分**硬约束**（如 CBRN 协助的绝对禁止）和**软编码默认值**（操作者可在定义范围内调整）。

> 训练时宪法在训练期间塑造模型行为，但**部署后难以修改，且无法被执行环境独立审计**。

## 部署时宪法：YAML 治理

**AutoHarness**（AIMing Lab, 2026）将治理规则编码在 YAML 文件中：

- 管线模式（核心/标准/增强）
- 风险分类模式
- 允许/拒绝的工具模式
- Token 预算限制
- 审计日志目的地

**声明式风格的关键优势**：
- 将治理意图与执行逻辑分离
- 非开发者利益相关者（安全团队、合规官）无需接触智能体代码即可审查和修改策略
- YAML 文件可用标准工具更新、版本化和差异比较

### 两层宪法的操作差异

| 维度 | 训练时宪法 | 部署时 YAML |
|------|-----------|------------|
| 修改成本 | 高昂 | 低（diff-reviewable） |
| 审计性 | 必须通过行为探测推断 | 直接可读 |
| 行为性质 | 概率性塑造默认行为 | 确定性检查 |
| 对抗鲁棒性 | 可被对抗提示覆盖 | 作为执行环境检查执行 |

## 可编程策略语言

在自由形式 YAML 和硬编码规则之间存在第三个设计点：**结构化策略 DSL**。

| 工作 | 方式 |
|------|------|
| **Progent 策略语言**（Shi et al., 2025a） | 布尔谓词、量词和环境引用——形式表达力 + 可读性 |
| **Formal-LLM**（Li et al., 2024） | 编码计划约束为下推自动机——序列排序约束、禁止工具组合、特定步骤的审批门 |
| **VeriSafeAgent**（Lee et al., 2025） | 将用户意图形式化为 UI 状态转换的 DSL，在 GUI 动作执行前验证 |

## 开放挑战

- 缺乏广泛采纳的标准宪法 schema——策略不可移植
- 验证宪法**内部一致性**（无矛盾规则）和**完整性**（无遗漏工具类别）的工具有限
- **训练时与部署时宪法的交互研究不足**：YAML 拒绝规则能否可靠覆盖 RLHF 强化的行为？
