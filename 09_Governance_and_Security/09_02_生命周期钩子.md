# 09.02 生命周期钩子

权限模型定义了**什么被允许**，生命周期钩子定义了**策略检查何时触发**。许多执行环境在智能体循环的每个阶段暴露钩子点，允许在不修改核心推理的情况下注入治理逻辑。

## 四钩子模型

```
H1: 输入验证 → LLM → H2: 动作验证 → 工具执行 → H3: 信息流控制 → 响应 → H4: 人机协同
```

| 钩子 | 触发点 | 功能 |
|------|--------|------|
| **H1** | 输入到达 LLM 之前 | 检测提示注入、验证输入 |
| **H2** | LLM 提议动作之后、工具执行之前 | 验证动作安全性 |
| **H3** | 工具执行之后、上下文返回之前 | 信息流控制、污点追踪 |
| **H4** | 敏感动作执行前 | 人机协同审批 |

## 各钩子详解

### H1：输入护栏

- **PromptShield**（Jacob et al., 2024）和 **DataSentinel**（Liu et al., 2025）：训练专用分类器检测提示注入
- 基于规则的检测器严格但脆弱；基于模型的检测器泛化更好但更慢且易受自适应攻击

### H2：输出护栏与动作验证

- **ShieldAgent**（Chen et al., 2025b）：将安全约束形式化为可验证谓词
- **ControlValve**（Jha et al., 2025）：约束智能体间控制流图，防止未经授权的智能体转跳

### H3：信息流控制与污点追踪

- **CaMeL**（Debenedetti et al., 2025）：每个数据值携带追踪来源的元数据标签——区分可信用户输入和不可信 Web 检索
- 自定义解释器强制执行不可信数据不能影响控制流决策

### H4：人机协同钩子

Codex、Gemini CLI、Cursor 和 OpenHands 等将破坏性或超出范围的动作交由用户显式批准。

**三个设计维度**：
- 验证范围（哪些动作需批准）
- 告警丰富度（用户看到多少上下文）
- 复发策略（允许一次 vs 始终允许）

**警告**：Felt et al.（2012）发现仅 17% 的 Android 用户在安装应用时注意权限对话框，仅 3% 正确回答了所授权限的理解问题——智能体审批对话框可能面临类似的**习惯化和理解风险**。

## 可编程执行基板

**AgentSpec**（Wang et al., 2026）：在规划、工具调用和响应阶段定义规则——触发器、谓词和执行动作。

**AgentDoG**（Liu et al., 2026a）：从单动作分类转向轨迹级诊断，按来源、故障模式和后果组织风险。

## 开放挑战

- 钩子 API 仍异构，缺乏广泛采纳的通用钩子接口标准
- 钩子引入延迟，**堆叠钩子的交互效应几乎未被研究**
- 上游净化器可能改变下游检测器依赖的信号，使组合管线弱于孤立组件
