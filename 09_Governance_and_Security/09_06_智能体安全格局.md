# 09.06 治理在智能体安全格局中的定位

## 威胁全景

治理机制回应一个具体的威胁格局。Kim et al.（2026）调查了 128 篇论文，编录了 **51 种攻击方法和 60 种防御方法**，跨七个设计维度：输入信任、访问敏感性、工作流、动作、记忆、工具、用户界面。

更高的灵活性扩大攻击面，**治理在运行时约束这种灵活性**：

| 治理机制 | 缓解或检测的风险 |
|---------|----------------|
| 权限模型与身份管理 | R1（不可信接口）、R5（数据泄露）、R6（未经授权动作） |
| 输入护栏 | R1、R2（错误指令跟随） |
| 输出护栏 | R2、R4（幻觉）、R5、R6 |
| 信息流控制 | R3（不受约束数据流）、R5、R6 |
| 组件加固 | R1、R2、R4 |
| 监控与审计 | R5、R6、R7（资源耗尽） |
| 人机协同 | R2、R6 |
| 权限分离 | R2、R3 |
| 形式验证 | R2、R6 |
| 声明式宪法 | 跨领域：配置以上所有 |

## 真实智能体的防御缺口

对六个智能体系统（Codex、Gemini CLI、OpenHands、Browser Use、Nanobrowser、Skyvern）的案例研究表明：**没有一个智能体完全实现了所有防御类别。**

- 信息流控制、身份管理和形式验证在所有受调查系统中**完全缺失**
- 监控是**部分的**——智能体记录工具调用但缺乏自动异常检测

## 纵深防御及其局限

Kim et al. 主张智能体安全需要互补的分层防御，但**分层不是免费的**——协调不善的层可能相互干扰，独立治理钩子的可组合性仍基本未被测试。

## 上下文安全：提议中的第四安全目标

Kim et al.（2026）提出将**上下文安全**（contextual security）作为传统机密性-完整性-可用性（CIA）三元组之外的候选第四智能体安全目标。Conseca 和 CaMeL 展示了工程方向：**上下文必须被视为受治理状态，而非被动的提示材料。** 是否应将其提升为独立安全目标尚无定论。
