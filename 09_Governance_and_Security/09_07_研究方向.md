# 09.07 研究方向

我们识别出八个治理特定的开放研究方向（更广泛的开放问题见 §12）：

### 1. 标准化策略与审计语言

每个执行环境定义自己的 YAML schema 和专有 DSL，碎片化治理生态。类比 MCP 对工具接口的标准化，社区驱动的规范将实现**可移植策略、可组合治理模块和跨执行环境审计互操作**。

### 2. 形式化治理保证

智能体行为的形式验证仍处早期阶段（Li et al., 2024; Chen et al., 2025b; Lee et al., 2025）。将这些技术扩展到**验证治理管线正确性**——例如证明宪法的内部一致性和工具类别覆盖完整性——仍探索不足。

### 3. 自适应治理

静态策略无法预见到每种任务上下文。Conseca 证明 LLM 生成的策略可弥合这一差距。**机器生成治理规则的可信度**，以及策略生成器本身应如何被治理，仍是开放问题。

### 4. 治理成本-效用权衡

更严格的治理降低风险但也降低智能体效用。目前缺乏在给定部署风险画像下校准治理强度的系统性方法论。需要量化框架来指导"治理到什么程度才足够"。

### 5. 跨组织治理协议

agent-permissions.json 指向跨组织边界的治理协调。从单个清单文件到完整的跨组织信任协商（如智能体到智能体合同的自动谈判）的路径尚未被探索。

### 6. 治理的对抗鲁棒性

治理机制本身可能被攻击。分类器和钩子可能被绕过；策略生成器可能被提示注入颠覆；审计日志可能被篡改。治理基础设施需要自己的威胁模型和防御。

### 7. 治理演进与生命周期管理

治理策略随部署经验和监管要求变化而演进。需要策略版本化、A/B 测试、灰度发布和回滚的形式模型——类比基础设施即代码的运动。

### 8. 人的因素与治理可用性

仅 3% 的用户正确理解其授予的权限（Felt et al., 2012）。设计智能体治理接口时需要**可用性研究**——审批对话框、策略配置界面和异常处理工作流——以防止习惯化和理解失败。
