# 09.01 权限模型与身份管理

任何智能体执行环境的第一个治理问题是**访问控制**：智能体可以触及哪些工具、文件、网络端点和系统资源？

智能体工作负载使这一问题比传统 RBAC 或 ABAC**更加困难**——因为所需的工具集通常取决于一个在部署时未知的自然语言任务。因此，文献沿**粒度轴**展开。

## 静态权限边界

生产编码智能体通常预定义权限范围，超出范围的动作需要升级审批：

| 系统 | 机制 |
|------|------|
| **Codex**（OpenAI, 2025） | 在受限文件系统和网络访问的沙箱中执行 shell 命令 |
| **Gemini CLI**（Mullen & Salva, 2025） | 工作区范围的文件访问 + 命令允许/拒绝列表 |

这些边界易于检查，但**无法表达任务特定意图**。

## 上下文依赖的权限控制

### Progent：运行时谓词 DSL

Progent（Shi et al., 2025a）引入了领域特定语言（DSL），其谓词涵盖工具名称、参数和环境状态。运行时在每次调用前评估谓词，允许最小权限策略随角色、用户或会话变化。

### Conseca：任务特定策略生成

Conseca（Tsai & Bagdasarian, 2025）从可信上下文生成任务特定策略，并用独立的确定性检查器强制执行。**策略生成与执行之间的分离**至关重要：生成组件可适应任务，而执行器保持可审计性。

## 身份管理与跨智能体访问控制

### 认证委托

South et al.（2025）认为智能体需要**认证委托**——扩展 OAuth 2.0 和 OpenID Connect 的框架，加入 User ID Token、Agent ID Token 和作用域委托 Token，将用户意图绑定到智能体特定权限。这一 token 链创建了从人类责任者到智能体动作的**可验证问责轨迹**。

### SAGA：多智能体身份

SAGA（Syros et al., 2025）在多智能体设置中引入**密码学一次性密钥注册**和短期访问 token，强制执行用户定义的智能体间联系策略。

### IsolateGPT：中心-辐条架构

每个第三方应用在隔离辐条中执行，拥有自己的 LLM、内存和工具访问。跨辐条通信通过可信中心传递——跨应用数据交换成为显式治理决策。

## 凭据管理

智能体常处理 API 密钥、会话 token 和一次性密码。将这些凭据暴露给 LLM 上下文会产生窃取风险。

**Skyvern**（Skyvern-AI, 2025）的模式：**密钥存储于保险库，仅向 LLM 暴露占位符**，仅在执行认证动作的自动化层替换真实值。

长周期会话的密钥生命周期管理仍是开放问题——token 可能中途过期或撤销。

## Web 级权限协调

**agent-permissions.json**（Marro et al., 2025）：轻量级清单文件，类似 `robots.txt`。网站所有者可声明智能体可使用哪些 UI 元素、速率限制、并发约束和需要人类确认的动作。

## 开放挑战

- **过于严格的策略降低智能体效用，过于宽松的策略否定治理目的**
- 缺乏跨执行环境可移植的标准权限规范语言
- 动作的归属身份问题：人类操作者？智能体实例？还是瞬态任务身份？
