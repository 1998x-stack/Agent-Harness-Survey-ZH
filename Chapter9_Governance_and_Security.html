§9.1 权限模型与身份管理
第一个治理问题：智能体可以触及哪些工具、文件、网络端点和系统资源？沿粒度轴展开——静态边界→上下文依赖→跨边界认证委托→Web级权限协调。
静态
Codex · Gemini CLI
预定义权限范围+命令允许/拒绝列表。易于检查，但无法表达任务特定意图。
上下文
Progent · Conseca
DSL谓词覆盖工具名/参数/环境状态。策略生成与执行分离——生成适应任务，执行保持可审计。
身份
SAGA · IsolateGPT
密码学一次性密钥+短期访问token。中心-辐条架构——跨应用数据交换成为显式治理决策。
凭据
Skyvern 模式
密钥存储于保险库，仅向LLM暴露占位符。长周期会话的密钥生命周期管理仍是开放问题。
委托
OAuth扩展
User ID Token + Agent ID Token + Delegation Token——从人类责任者到智能体动作的可验证问责链。
Web级
agent-permissions.json
类似robots.txt的轻量级清单——声明可用UI元素、速率限制、需人类确认的动作。治理开始跨越组织边界。
§9.2 生命周期钩子 · 四钩子模型
权限模型定义了什么被允许，钩子定义了策略检查何时触发。四个钩子点沿一次工具使用周期分布——允许在不修改核心推理的情况下注入治理逻辑。
H1 · 输入护栏
输入 → LLM 之前
PromptShield · DataSentinel
检测提示注入
规则严格但脆弱 · 模型泛化好但慢
H2 · 动作验证
LLM → 工具 之前
ShieldAgent · ControlValve
安全约束形式化为可验证谓词
防控制流劫持攻击
H3 · 信息流控制
工具 → 上下文 返回前
CaMeL · 污点追踪
区分可信输入 vs 不可信检索
不可信数据不能影响控制流
H4 · 人机协同
敏感动作执行前
仅17%用户注意权限对话框
仅3%正确理解授予的权限
习惯化和理解风险需警惕

AgentSpec定义规则（触发器+谓词+执行动作），AgentDoG转向轨迹级诊断。钩子API仍异构——缺乏广泛采纳的通用标准——且堆叠钩子的交互效应几乎未被研究。

§9.3-§9.5 组件加固 · 声明式宪法 · 审计
组件加固 §9.3

指令层级：模型优先处理系统提示。Llama Guard：独立分类器跨LLM后端复用。ETDI：密码学签名工具定义防rug-pull。slopsquatting：21.7%幻觉包名可被恶意注册。

声明式宪法 §9.4

训练时宪法（Anthropic四层优先级：安全>伦理>合规>有用性）vs 部署时YAML（AutoHarness三管线：核心/标准/增强）。YAML可版本化、diff-reviewable——非开发者可审查策略。

审计基础设施 §9.5

AutoHarness JSONL逐工具调用记录。逐动作检测（廉价）vs 轨迹级检测（捕获多步攻击）。分层管线：核心→标准→增强。缺乏标准化审计schema。

§9.6-§9.7 安全格局 · 研究方向
威胁全景

Kim et al.编码51种攻击方法、60种防御方法，跨七个设计维度。Chen et al.综合50篇论文，六维分类法。治理机制映射到七风险类别（R1-R7）。

八项研究方向

标准化策略语言 · 形式化治理保证 · 自适应治理 · 成本-效用权衡 · 跨组织协议 · 对抗鲁棒性 · 治理演进 · 人的因素——仅3%用户正确理解授予的权限。

上下文安全（Kim et al.提议的第四安全目标）：上下文必须被视为受治理状态，而非被动的提示材料。Conseca和CaMeL展示了工程方向——是否应提升为独立安全目标尚无定论。纵深防御分层互补，但协调不善的层可能相互干扰，独立治理钩子的可组合性仍基本未被测试。
