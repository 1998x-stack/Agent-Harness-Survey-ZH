# 08.02 阶段二：执行前就绪验证

第二阶段回答：**评估能否被公平和可复现地运行？** 这一阶段在基准排行榜上通常不可见，但对执行环境评估至关重要。

## 三层就绪验证

### 环境与沙箱就绪

检查沙箱、仓库、浏览器、终端或 VM 是否从**已知基线**启动：

- **软件工程**：仓库快照、依赖关系、任务设置、测试可执行性
- **浏览器/计算机使用**：网站重置、浏览器配置文件、桌面状态、服务可用性

| 系统 | 贡献 |
|------|------|
| **SWE-bench** | 可执行仓库状态 + 基于测试的验证 |
| **Terminal-Bench** | 受控环境 + 验证逻辑的终端任务 |
| **OSWorld** | 真实计算机环境 + 基于执行的评估脚本 |
| **Repo2Run**（Hu et al., 2025a） | 自动化 Docker 环境设置 |
| **HAL**（Kapoor et al., 2025） | 标准化、成本感知的评估基础设施 |

> 环境重置和依赖验证是**测量仪器的一部分**，而非可选项。

### 工具、上下文和权限就绪

就绪验证是**跨层的**：

| 维度 | 检查内容 | 风险 |
|------|---------|------|
| **工具就绪** | API、MCP 服务器、浏览器控制、shell 命令、文件操作是否可用且一致描述 | 工具描述变化 → 不同运行测量不同的动作空间 |
| **上下文就绪** | 历史记录、记忆存储、草稿本、检索文档是否重置或有意图地初始化 | 未重置 → 智能体可能从泄漏的状态中获益 |
| **权限就绪** | 文件访问、凭证、网络访问、审批门是否匹配基准规范 | 过严 → 能力强的智能体因治理原因失败；过松 → 不安全行为未被检测 |

**SWE-agent、SWE-ReX 和 OpenHands** 表明：工具暴露、shell 访问、浏览器访问、执行后端和运行时接口与评估设计不可分离——**智能体-计算机接口决定了哪些动作是可能的，从而决定了基准实际测量的是什么**。

### 评估器与评分器就绪

评估器本身也必须在执行前验证：

- **确定性评分器**：检查不稳定性、缺失依赖、与环境状态的兼容性
- **LLM-as-Judge**：提示、评分标准和评判模型应版本化
- **人工审计协议**：应预先定义

> 评估器就绪是**有意义的故障归因的前提条件**。
