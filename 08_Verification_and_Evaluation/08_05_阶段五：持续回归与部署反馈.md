# 08.05 阶段五：持续回归与部署反馈

最终阶段回答：**评估结果如何驱动下一次执行环境修订？** 智能体执行环境持续演进——提示、工具模式、MCP 服务器、上下文策略、沙箱镜像、编排循环、治理规则和评判提示都可能随时间变化。

## 执行环境变更的回归评估

回归评估应由**执行环境变更和模型变更**共同触发。工具描述、上下文压缩策略、沙箱镜像、权限规则或评判提示的变更都可能改变智能体行为或评估分数。因为执行环境组件相互交互，局部改进可能产生全局回归。

### 分层评估套件

实践模式是维护一个分层评估套件：

| 层级 | 内容 |
|------|------|
| **单元级** | 工具模式测试、确定性验证器 |
| **单步级** | 局部决策测试 |
| **完整 rollout** | 端到端完成测试 |
| **多轮模拟** | 长周期连贯性测试 |

**LangChain** 的深度评估指南反映了这一分层视图（LangChain, 2025b），**Anthropic** 将评估框定为可在开发期间运行的带有显式评分逻辑的自动化测试（Anthropic, 2026b）。

## 评估框架与 LLMOps 集成

| 框架 | 聚焦 |
|------|------|
| **Promptfoo** | 提示和 LLM 应用的回归测试 |
| **DeepEval** | 单元测试式抽象 |
| **RAGAS** | 检索增强生成评估 |
| **lm-evaluation-harness** | 标准化语言模型评估 |

评估还应与可观测性（§7）连接：**生产追踪可以成为回归测试，评估失败可以成为可观测性信号。** 这一链接闭合了监控发生了什么与构建受控测试来复现和诊断它之间的循环。

## 验证器导向与训练时评估

一个较新的方向将评估器不仅用作离线指标，还用作**训练信号和优化目标**：

- **R2E-Gym**：使用环境反馈作为改进智能体策略的奖励或验证信号（Jain et al., 2025）
- **Meta-Harness**（Lee et al., 2026）：将执行环境设计本身作为自动化搜索的对象——不仅评估哪个模型在固定执行环境下表现最好，还探究哪个执行环境结构、提示策略、工具接口或控制循环产生更可靠的智能体行为

> 在这一框架下，评估不是管道的终点，而是**使执行环境得以改进的信号**。
