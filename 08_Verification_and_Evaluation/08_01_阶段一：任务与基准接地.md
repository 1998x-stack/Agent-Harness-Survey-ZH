# 08.01 阶段一：任务与基准接地

第一阶段回答的是最基础的问题：**评估的是什么？**

对于 LLM 智能体，任务不仅是一个自然语言提示，而是一个**嵌入性问题**，由环境状态、可用工具、允许动作、约束条件、终止条件和成功标准共同定义。没有良好指定的环境和成功条件，后续的分数就无法被可靠解读。

## 三大基准类别

### 软件工程与终端任务

软件工程基准因为结合了**现实任务与可执行结果验证**，是智能体评估中最成熟的形式之一：

| 基准 | 核心机制 |
|------|---------|
| **SWE-bench**（Jimenez et al., 2024） | 将每个任务接地到真实 GitHub issue 和仓库快照，通过运行测试评估生成的补丁是否解决 issue |
| **Terminal-Bench**（Merrill et al., 2026） | 扩展到命令行工作流，智能体通过编辑文件、运行命令、设置依赖和解读故障与终端环境交互 |

**核心洞察**：强大的结果验证器需要强大的任务接地。测试只有在仓库状态、依赖关系和预期成功标准被精确定义时才能作为可靠的评估器。否则，失败的测试可能反映补丁无效，但也可能反映不一致的环境或欠指定的基准实例。

### Web、浏览器和计算机使用任务

这类基准将任务接地到交互式环境，成功由浏览器、桌面或应用程序状态的变化定义：

| 基准 | 聚焦 |
|------|------|
| **WebArena**（Zhou et al., 2024） | 真实的 Web 环境 |
| **VisualWebArena**（Koh et al., 2024） | 多模态 Web 任务 |
| **BrowserGym**（Chezelles et al., 2024） | 通用浏览器智能体研究基板 |
| **WorkArena**（Drouin et al., 2024） | 基于 ServiceNow 的知识工作 |
| **OSWorld**（Xie et al., 2024） | 真实计算机环境——桌面应用、文件、多应用工作流 |

这类基准揭示了：**浏览器和计算机使用评估同时是评估问题和环境设计问题**。基准必须提供逼真接口、隔离任务状态、暴露适当观察并定义可测量的成功谓词——这在执行环境层和评估层之间创建了直接桥梁。

### 跨领域和企业工作流任务

第三组基准跨异构工具、环境和工作流测试更广泛的智能体能力：

| 基准 | 范围 |
|------|------|
| **AgentBench**（Liu et al., 2023a） | 操作系统、数据库、Web 浏览、游戏 |
| **GAIA**（Mialon et al., 2023） | 通用助手任务——推理、工具使用、多模态信息访问 |
| **TheAgentCompany**（Xu et al., 2024） | 工作场所式数字劳动模拟 |
| **WorkArena / WorkArena++**（Boisvert et al., 2024） | 企业工作流——成功依赖导航复杂软件 |

这一基准家族的**主要贡献是覆盖度**：它测试执行环境能否跨任务类型、工具接口、状态表示、工作流和成功条件泛化。
