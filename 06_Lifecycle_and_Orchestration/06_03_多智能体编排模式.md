# 06.03 多智能体编排模式

多智能体编排通过**组合具有专门角色的多个智能体**来扩展单智能体循环。不再要求一个智能体独自完成规划、执行、检查和修订，多智能体执行环境可以跨智能体或子智能体分离这些职责。

这一结构支持**任务分解、并行探索、批判、验证和聚合**，使其比孤立的循环更适合复杂任务。

## 五大编排模式

| 模式 | 描述 | 代表系统 |
|------|------|---------|
| **层级编排**（Hierarchical） | 高层控制器向智能体/子智能体分配工作并整合输出 | DeerFlow（6.7万★）、AutoGen（5.8万★）、OpenAI Agents SDK、DeepAgents |
| **团队编排**（Team） | 将一组专门智能体作为协调团队暴露，各有不同的命名职责 | oh-my-claudecode（3.4万★） |
| **工作流编排**（Workflow） | 将智能体和工具组织为显式阶段或控制逻辑 | Semantic Kernel（2.8万★） |
| **扇形展开**（Fan-out） | 并行运行多个智能体探索多样化方案 | Emdash（4千★） |
| **图组合**（Graph） | 将智能体、工具或状态表示为交互图中的节点，允许多种协调模式共存 | LangGraph（3.2万★）、Hive（1万★） |

## 执行模型

这一层级的执行通常是**有状态或混合的**，因为多智能体系统必须维护：

- 协调状态
- 角色分配
- 任务图
- 共享工件
- 中间结果

## Anthropic 的规划器-生成器-评估器架构

Anthropic 的三角色架构（Anthropic, 2025e）揭示了更广泛的原理：

> **规划、执行和验证可以被分离为显式角色**，从而改善分解和鲁棒性，同时也增加协调开销（Anthropic, 2026c）。

这一架构的设计表明：多智能体编排不是在单个智能体上加一层包装那么简单——它涉及在**分解收益与协调成本之间做出显式的工程权衡**。
