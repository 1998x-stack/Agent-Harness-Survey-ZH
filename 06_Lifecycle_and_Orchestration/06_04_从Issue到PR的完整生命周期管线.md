# 06.04 从 Issue 到 PR 的完整生命周期管线

完整生命周期编排管理从**规格说明到验证输出**的整个任务工作流。在这一层级，关注点不仅是智能体如何交互，更是执行环境如何支撑跨规划、实现、验证、审查和交付的长周期执行。

## 核心抽象：任务运行器

**任务运行器（task runner）** 是这一层的核心抽象：一个管理调度、状态持久化、重试、验证和迭代精化的执行环境，覆盖完整的任务生命周期（OpenAI, 2026a; LangChain, 2026b）。

执行被落地到持久化工件上：
- 仓库（repositories）
- Issue
- 分支（branches）
- 文件（files）
- 测试（tests）
- Pull Request

## 典型工作流

```
Issue / 任务规格
    ↓
智能体规划
    ↓
代码或工件生成
    ↓
验证
    ↓
人工审查
    ↓
PR 接受
```

## 层级组合关系

概念上，完整生命周期管线是对前两层抽象的**组合**：

| 组件 | 角色 |
|------|------|
| **单智能体循环**（§6.2） | 提供执行原语 |
| **多智能体模式**（§6.3） | 提供协调能力 |
| **任务运行器** | 将它们集成为端到端工作流 |

最终的运行模式是：**人类掌舵，智能体执行。**
