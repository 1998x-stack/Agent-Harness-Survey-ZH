# 06 生命周期与编排（L）

生命周期与编排层（Lifecycle and Orchestration）关注智能体系统如何**跨多次模型调用、工具调用、故障、修订和交接来推进任务**。这是 ETCLOVG 的第四支柱。

## 核心问题

在长周期任务中，可靠性不仅取决于模型能否产生好的下一步动作，还取决于执行环境能否：

- 记住已经发生了什么
- 决定接下来应该发生什么
- 从错误中恢复
- 协调子任务
- 在任务完成时停止

（OpenAI, 2026b; Anthropic, 2025d; 2026c）

## 三层组织

| 层级 | 描述 | 代表系统 |
|------|------|---------|
| **单智能体内部循环**（§6.2） | 一个智能体观察→决策→行动→反馈的重复循环 | OpenCode（15.9万★）、Claude Code（12.3万★）、Gemini CLI、Codex CLI、Aider、SWE-agent |
| **多智能体编排**（§6.3） | 将多个具有专门角色的智能体协调组合 | DeerFlow（6.7万★）、AutoGen（5.8万★）、LangGraph、OpenAI Agents SDK |
| **完整生命周期管线**（§6.4） | 从 Issue → 代码变更 → 测试 → 审查 → PR 的端到端工作流 | Vibe Kanban（2.6万★）、Symphony（2.4万★）、GitHub Agentic Workflows |

## 有无状态的设计分歧

| 执行模型 | 描述 | 优势 | 代价 |
|---------|------|------|------|
| **无状态重放**（Stateless replay） | 从记录的交互历史重建运行 | 可复现、可审计 | 轨迹增长时代价升高 |
| **有状态执行**（Stateful） | 在文件、数据库、仓库、任务图或服务中持久化操作状态 | 连续性、恢复能力 | 一致性和调试挑战 |
| **混合模式**（Hybrid） | 可重放历史 + 持久化工件结合 | 取两者之长 | — |

大多数实际系统采用混合设计。
