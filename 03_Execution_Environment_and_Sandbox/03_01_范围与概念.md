# 03.01 范围与概念

## 3.1.1 定义

智能体的**执行环境**（execution environment）是指智能体动作被实际执行的基础设施层。在 LLM 智能体的语境中，执行环境与沙箱是紧密耦合的概念——生产级智能体系统几乎无一例外地在沙箱化环境中执行动作。

## 3.1.2 为何沙箱在智能体时代成为核心关切

智能体时代的沙箱化不仅仅是继承自传统多租户代码执行的安全措施。它同时服务于三个截然不同的目的，而三者的组合正是将沙箱从运维细节提升为执行环境设计中一级关切的原因。

### 目的之一：安全（Security）

智能体沙箱面临的安全挑战超越了传统多租户代码执行的范畴：

- **LLM 生成的代码无法在大规模下审计或预测**，排除了将静态审查作为主要防御手段的可能
- **智能体跨多步自主执行**，在动作执行时刻无法获得人类干预
- **提示注入攻击可以将原本良性的智能体转化为针对沙箱的攻击向量**，模糊了可信用户意图与恶意输入之间的边界

最近的沙箱逃逸实证研究表明这些担忧并非假设（§3.3 将提供量化证据）。

### 目的之二：可复现性（Reproducibility）

长周期智能体任务及其评估执行环境（§8）要求具备将执行状态重置到已知基线的能力：

- Docker 容器或 microVM 可以按需销毁和重建，而开发者的工作站做不到
- 这一特性使得 SWE-bench（Jimenez et al., 2024）和 OSWorld（Xie et al., 2024）等基于沙箱的评估标准变得切实可行
- 在训练阶段，单个任务可能沿数百条并行轨迹重放，**缺乏廉价的复位机制本身就是可扩展性瓶颈**

### 目的之三：活性（Liveness）

这是智能体时代最独特的目的。没有沙箱的情况下，智能体希望执行的每一个可能有风险的动作——文件写入、软件包安装、出站网络调用——都必须经过显式的人类权限提示才能放行。

在大规模下，这产生两种失败模式：

1. **用户因挫败感而放弃智能体**
2. **用户条件反射式地批准所有操作**，使安全提示的防护意义荡然无存

沙箱通过定义一个**有界区域**来打破这一僵局——在该区域内，智能体被授权自由行动。权限从"每个动作都要问"转变为"会话配置层面的一次性设定"。

> Anthropic 报告称，为 Claude Code 引入沙箱化后，权限提示减少了 **84%**，同时保持了安全性（Anthropic, 2025b）。

在这一框架下，沙箱同时是**牢笼**和**许可证**——正是许可证的一面，使自主长周期执行成为可能。

### 三重目的的独特组合

| 目的 | 与传统沙箱的关系 | 智能体时代的特殊性 |
|------|-----------------|-------------------|
| 安全 | 共享 | 提示注入、自主多步执行放大威胁 |
| 可复现性 | 被放大 | 评估和训练的规模化需求 |
| 活性 | **全新** | 无沙箱则长周期自主执行不可行 |

三者组合的独特性证明了将智能体沙箱视为独立研究对象——而非容器技术的下游应用——的合理性。
