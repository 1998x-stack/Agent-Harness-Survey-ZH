# 03.04 部署模式

智能体沙箱基础设施已从最初的自托管 Docker 模式分化为多种部署模式。三种模式在当前的实践中并存：

## 三种部署模式

| 模式 | 描述 | 代表系统 |
|------|------|---------|
| **自托管（Self-Hosted）** | 开发者直接管理沙箱基础设施 | OpenHands、SWE-agent 的默认模式 |
| **云（SaaS）** | 沙箱即服务提供商处理基础设施 | E2B、Modal、Daytona Cloud |
| **混合/自带云（BYOC）** | 智能体逻辑与沙箱执行跨环境解耦 | OpenHands SDK 的 Local/Remote Workspace、E2B/Northflank 的 BYOC |

## 驱动演进的两股力量

### 力量一：工程权衡的三轴

实践者报告将部署选择归纳为**延迟、安全性和可扩展性**三个轴上的权衡：

- **自托管**：最低延迟、最紧密的迭代循环，但承担全部运维负担
- **云沙箱**：弹性扩展 + 托管安全，代价是网络往返延迟
- **混合模式**：尝试在保留敏感数据本地的同时委托执行能力

### 力量二：组织约束

数据驻留、合规性和可审计性等组织需求推动部署向混合架构靠拢，即使纯从延迟和可扩展性角度考虑，单一模式可能是最优解。

## 小结

部署模式的选择不再是纯粹的技术决策。随着智能体从原型走向生产，**数据治理和合规性正成为与延迟和性能同等重要的一级约束**，推动着从单模式部署向混合架构的结构性转变。
